# Automatic ImplDmNote rendering

Run the renderer-compatible ImplDmNote app alongside ADOFAI. The app announces its native render capability through the existing ADOFAI-IPC namespace `tuf-replay-renderer`; the web renderer offers ImplDmNote when a compatible app is connected. Render acquires the app session before changing game state and releases it after composition, failure or cancellation. Consumers need no source checkout, frozen snapshot file, Node, Chrome or separate OBS connection.

The independent GPL renderer and GPL app communicate through data messages. The proprietary recorder has no ImplDmNote code dependency. The app owns its installed frontend and native runtime: WKWebView on macOS, WebView2 on Windows.

## Session protocol 2

ADOFAI IPC 1.0.0 carries control messages over one WebSocket session on `/ipc/ws` with wire protocol 3. The app subscribes to `tuf-replay-renderer` and sends `dmnote.attach` with `applicationId`, `protocolVersion: 2`, `applicationVersion`, `platform`, `nativeCapture` and `multiViewerCapture`. The correlated `dmnote.attached` event confirms attachment. The authenticated peer and connection own the render session; another app cannot take over an active session. Domain command handlers and message listeners never block Unity's frame thread.

The renderer sends `dmnote.begin`, `dmnote.reset`, `dmnote.frame` and `dmnote.end` directly to the owning app. The corresponding events are `dmnote.begun`, `dmnote.reset`, `dmnote.frame.ready` and `dmnote.ended`, each carrying the command ID as `correlationId`. A correlated `dmnote.failed` carries `{code,message}`. An acceptance message alone does not complete an operation. Duplicate command IDs return the cached outcome without repeating capture or session side effects.

Begin freezes the current preset, selected hand/foot tabs, custom CSS/JS, current plugin panel layout, plugin storage, local storage and local asset bytes. It gates the native keyboard/mouse/HID/shortcut consumer before counters, sounds, plugin input or live viewer events. Begin returns a `surfaces` array (one or two entries), each with `viewerKind`, width/height, `frameFormat` (`rgba` or `png`), an optional normalized `layout` and its own temporary frame directory. Manual single-viewer sessions may return the same descriptor at the top level. Reset recreates all isolated surfaces from the same frozen data after the game pass calibrates its timeline; it retains the input gate.

Automatic placement is enabled by default. The game supplies its process ID, current drawable viewport and requested video dimensions. The renderer requests `includeVisibleViewers: true` and requires the app's `multiViewerCapture` capability. The app includes each visible hand/foot overlay and reads its live window and game window metadata before rendering changes the game viewport. Each viewer retains its own selected tab and a separate small capture surface; the empty space between windows is never captured. Hidden viewers are excluded and foot-only rendering works. Older apps show an update message instead of silently losing the foot overlay. It preserves the overlay's position and size relative to the game's content area, including negative desktop coordinates and partial offscreen placement. The render surface retains the live CSS viewport while captured pixels use the final video size. On macOS, window metadata is in points and the game title bar is excluded using Unity's drawable aspect ratio; Windows uses the native client rectangle. To use explicit `width`, `height`, `left`, `top` and `scale` instead, set `dmNote.automaticPlacement` to `false`; `dmNote.viewerKind` continues to select a single `hand` or `foot` viewer in that mode.

If initialization fails specifically with `render-game-window-missing` or `render-game-viewport-invalid` (or the structured `dmnote_game_window_unavailable` code), the renderer cleans up that attempt and waits for Unity's game focus. Web and game progress show the reason, a 30-second limit and cancellation. It retries only while focused, with a 500 ms backoff, refreshing Unity's viewport dimensions on every attempt. The deadline starts at the first window-lookup failure and is not extended by retries. `dmnote_game_focus_timeout` means the game never received focus; `dmnote_game_window_timeout` means focus arrived but its bounds remained unreadable. Other messaging/capture failures are not retried or recategorized, and manual placement bypasses this recovery. Legacy native window error identifiers remain recognized by this retry policy.

A frame has `sessionId`, monotonically increasing `frameIndex`, integer `outputTimeUs`, integer `replayTimeUs`, and recorded events `{key,down,sequence,outputTimeUs,replayTimeUs}`. Keys are symbolic Unity KeyCode names from bundle version 1. Input timestamps map through the recorded effective pitch and advance at rate 1 after clear. Equal-timestamp ordering preserves the CSV sequence; negative preroll inputs and down/up pulses entirely between frames remain intact.

The surface applies inputs and samples its virtual clock, timers, rAF, CSS animations, React state and WebGL at the requested output time. Native snapshot completion provides the paint barrier. The ACK has a `frames` array with one entry per surface in begin order, containing `viewerKind`, the exact frame index/time and frame path. Manual single-viewer sessions return the frame at the top level. Every selected viewer must acknowledge the frame before the session advances; a missing or mismatched foot frame fails explicitly. On macOS, the snapshot uses the final pixel width and copies straight-alpha RGBA off the UI thread without TIFF/PNG encoding or decoding. Windows retains PNG capture. Each viewer retains only `frame.rgba` or `frame.png` and its temporary replacement; the renderer validates raw byte count and waits until FFmpeg consumes it before requesting another frame. A validated streaming CSV cursor keeps the alpha pass independent of recording length. Each viewer streams to a bounded FFmpeg pipe producing a lossless alpha FFV1 intermediate using its fast coder; final composition places both at their independent layouts. Frame completion wakes the IPC coordinator immediately. Only one frame is in flight: all selected viewer files are validated and fully copied into their FFmpeg pipes before the renderer sends another frame command. Pending captures still accept an independent End command. The app emits `dmnote.pulse` once per second using the main window's physical wall clock, which continues independently of the virtual render clock. The media composer uses the frozen automatic layout or the explicit manual settings.

## Isolation and cleanup

The private webview has a nonpersistent data store and an in-memory native API shim. Preset, counter and plugin writes stay inside it. Render counters start at zero because recordings do not contain the original live counter baseline; replaying over the post-clear cumulative counter would count the run twice. Existing live counts are never rewritten.

The app listens for direct commands while native capture is pending, so End can interrupt a stalled frame. End destroys all private surfaces, deletes their frame caches and re-enables real input. Session boundaries release live held-key indicators to avoid stuck keys after ignored physical key-up events. A transport or namespace disconnect ends the app's native session immediately; a physical wall-clock backend watchdog is the 15-second cleanup fallback.

The renderer expires an app lease after eight seconds without a pulse, even if the WebSocket transport still responds. Expiry or owner disconnect fails pending frames, publishes `dmnote.availability.changed` with unavailable state, and cancels the render that owned that session. A queued cancellation cannot affect a later job or a newly enabled renderer. The renderer stops FFmpeg and removes incomplete alpha files on cancellation. Lease deadlines and local-peer listeners are released on disable/unload.

The whole overlay is captured: DOM keys/text/counters/statistics/plugin panels and WebGL notes. Plugins using normal recorded-key, raw-key, statistics and clock APIs work in this surface. Plugins requesting live app actions, external-process state, separate Worker clocks or new network data require a replay-specific contract. Local fonts/images and bundled frontend assets are retained by the app; remote dynamic resources need to be stable and load successfully during preparation.

## Verification and distribution

Renderer: `./scripts/run.sh dmnote-check` tests actual bridge/session code with an isolated app transport, exact pitch/preroll mapping, streaming hand/foot FFmpeg alpha output, missing-foot rejection, independent placement, frame ordering, authenticated ownership, deterministic wall-clock lease expiry and renewal, stale deadline isolation, cancellation cleanup and unavailable push without transport loss.

ImplDmNote: `./scripts/run.sh desktop-check` runs frontend/IPC cancellation regressions, game-relative coordinate tests and offline native compilation. `desktop-render-test` creates a hidden, nonpersistent macOS WKWebView using synthetic data only. It compares PNG and RGBA alpha, colors, orientation, conversion time, between-frame taps, held keys, mouse mapping, an updating custom plugin panel/storage and identical hashes across two 40-frame sessions per format plus two distinct foot-preset sessions. It never starts the user's app or input daemon. macOS native compilation and runtime fixture are verified; Windows capture still needs a Windows run.

`./scripts/run.sh desktop-bundle` creates an embedded app bundle in the app repository. On macOS it signs the app/helper locally, verifies the signature and writes `Release/ImplDmNote-Renderer-macos-<arch>.zip`. This development artifact is not installed or launched by the workflow. The renderer package contains its bridge and these docs rather than a browser/export-helper runtime. Run the patched app after quitting an older running build; the existing single-instance behavior otherwise brings the older app forward.
