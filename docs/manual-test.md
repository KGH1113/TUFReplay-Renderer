# 실게임 확인

자동 빌드·데이터 계약·FFmpeg 합성·ImplDmNote 브라우저 테스트와 실제 게임 검증을 구분합니다. 실행 중인 게임은 개발 과정에서 재시작하거나 변경하지 않았습니다.

첫 버전은 0번 타일부터 시작한 전체 플레이를 지원합니다. 중간 타일에서 시작한 기록은 렌더 전에 안내하며, 필요한 타이밍·판정 정보가 없는 예전 기록은 새로 녹화해야 합니다.

이번 작업의 설치 파일은 `~/dev/src/tuf-replay-render/build/TUFReplay.zip`, `~/dev/src/OrbitRender/OrbitRender/bin/Release`, `~/dev/src/TUFReplay-Renderer/Release/TUFReplay-Renderer`에 있습니다. 설치 폴더를 바꾸기 전 게임을 종료합니다. 새 웹 화면은 다음 명령으로 실행합니다.

```sh
cd ~/dev/src/tuf-replay-render
./scripts/run.sh web-dev
```

1. 새 TUFReplay 패키지, OrbitRender의 리플레이 드라이버 커밋, `Release/TUFReplay-Renderer`를 각각 설치합니다. 게임을 재시작하고 모드 세 개를 활성화합니다. 웹도 `codex/replay-rendering` 작업 폴더의 빌드로 실행합니다.
2. 원래 레벨과 필요한 게임 모드가 설치된 최근 클리어 기록으로 **Render → 1080p60**을 실행합니다. 판정 수, 마지막 타일, 클리어 시점과 영상 길이를 일반 리플레이와 비교합니다.
3. 카메라의 위치·크롭·좌우 반전·보정 시간을 확인합니다. 마이크의 시작 시점·음량을 확인하고 게임 오디오가 함께 남아 있는지 듣습니다. 배속 기록도 한 번 확인합니다.
4. 키뷰어에서 짧은 입력, 동시에 누르는 키, 홀드, 키 횟수와 레인 효과를 확인합니다. Overlayer의 텍스트와 마스크가 보이는지 확인합니다. 작업 상태의 호환성 경고를 함께 봅니다.
5. 준비·게임 렌더·미디어 합성 단계에서 각각 취소해 봅니다. 게임 속도·입력 오프셋·키뷰어 누적 횟수·사용자 설정이 복구되고 다시 렌더할 수 있어야 합니다. 가상의 재생이 실제 클리어 기록이나 개인 키 횟수를 저장하면 실패로 취급합니다.
6. 완성 영상을 다운로드하고 앞·중간·끝 부분의 동기화를 확인합니다. ImplDmNote는 `renderer.settings.json`과 고정 프리셋을 준비한 뒤 확인합니다. 프리셋의 카운터는 고정한 시점의 값에서 시작하며 실제 앱의 카운터는 바뀌면 안 됩니다.

문제가 생기면 기록 ID, 사용한 모드 버전, 작업 상태의 경고·오류, 게임 로그의 `TUFReplay-Renderer`/OrbitRender 부분을 함께 남깁니다. 기록을 처음 내보낸 뒤 레벨이 바뀌면 다시 내보내야 합니다.
